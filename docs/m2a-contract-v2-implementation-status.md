# M2a Contract v2 Implementation Status

**Status:** Initial implementation proposal on `m2a-contract-v2-foundation`. This is not merged, does not freeze Phase 0, and is not a verified M2a release.

## Included in this proposal

- `contracts/v2/pipeline.yaml` and `contracts/v2/tlc-yellow-v2.json` define the semantic schema, audited source cohort mappings, the D2 one-day half-open pickup window, and the distinct exact and distribution month ranges.
- `load_contract(root, version="v1")` preserves the v1 default. Selecting v2 validates the contract/schema pair, the pinned audit digest and version, the complete 48-month inventory, cohort signatures, explicit physical type mappings, and required semantic columns. The audit digest is UTF-8 JSON with newline normalization, explicitly declared in the contract and stable across Windows and Linux.
- `build_v2_source_provenance` validates a source file's exact bytes, size, row count, ordered physical schema and cohort against the pinned audit. It returns portable provenance without machine-specific paths and keeps physical and normalized schemas separate.
- The run API and CLI accept `contract_version="v2"` or `--contract-version v2`; they continue to default to v1. A v2 run normalizes source column names from the contract and applies the D2 one-day half-open pickup window as a first-failure rejection rule with per-rule counts, but does not alert or fail the month for spill. Provenance-valid synthetic Parquet files from each of the three physical schema cohorts have passed through the actual worker subprocess, report validation, materialization and publication path.
- `experiments/m2a/verify_v2_run.py` independently reloads the source Parquet and lookup CSV, recomputes cleaning, join and daily metrics with the Polars reference path, validates row-level output tables against that recomputation, checks contract and manifest consistency, and confirms that `CURRENT` reflects the publication decision. Fixture coverage includes all three source schema cohorts and detects a modified materialized table. This verifies the test fixtures only, not a full TLC month.
- The [Kaggle smoke notebook](https://www.kaggle.com/code/ananyatiwari0212/dic-m2a-v2-smoke-5356606), version 4, completed the audited January 2023 run on source commit `551886a36784f5595522430bde61e3e1f5449ec4`. It processed 3,066,766 source rows, retained 2,998,860, and published run `8b914662bbf84586ba7847204794e974`. Independent reconciliation found zero missing or unexpected rows in all four output tables, including 6,545 daily zone metrics. The downloaded evidence ZIP has SHA-256 `47408b07eed10c8334358cc5551a8c568ae5d7e692dd321e6b41eaa9dead3236`. Its archive integrity and local source and lookup hashes were checked after download. The upload and retrieval steps are in `docs/m2a-kaggle-v2-smoke.md`.
- In version 3, four daily averages differed at exact decimal ties. Contract v2 now calculates the mean with exact arithmetic and rounds ties away from zero at six decimal places. The independent verifier was unchanged for the passing rerun.
- An independent Polars reference module now covers ingestion reconciliation, cleaning and first-failure counts, timestamp offsets, join cardinality/key behavior, and sum/mean aggregation. Hand-computed fixtures cover the reference transformations for all eight catalog mechanisms and directly applicable threshold/offset values. These are oracle unit fixtures, not the catalog's full severity and seed matrix. Polars 1.44.2 and its runtime are isolated in a separate pinned oracle dependency file and installed in CI.
- `experiments/m2a/fault_hooks.py` defines deterministic injection hooks for the catalog mechanisms. The development entry point rejects held-out cases and returns pipeline inputs separately from evaluator facts.
- `experiments/m2a/run_development_case.py` connects the duplicate lookup key hook to the v2 worker. It runs a clean control and a blocked case in a fresh workspace, independently checks materialized stages and per-group deltas, and compares the publication pointer byte for byte.
- The same runner accepts `--case duplicate-ingestion`. It independently verifies that the modified Parquet contains the original rows followed by exact copies of the seeded selection. The v2 source audit rejects the modified file before staging outputs, and the worker records the failure with the clean publication pointer intact. This is a source audit detection exercised on a fixture. Comparisons that omit trusted source identity still need a benchmark path for observing the downstream effects.
- The development runner now executes the cleaning fare threshold and aggregation sum-to-mean mutations in the v2 worker. It independently checks each materialized stage against the verified clean result and the expected mutation. The aggregation preserves the revenue column's decimal type and rounds the substituted mean directly to cents. Both mutations passed through the existing publication checks in isolated fixtures. A production detector or publication gate for either fault has yet to be implemented.
- All four development cases write evaluator facts outside the worker directory after execution. Full isolation across comparison methods remains open.
- The development runner accepts `--ledger` with a JSONL journal path. Keep the same journal and workspace across runs. It reuses a completed attempt only when the case settings, input and contract hashes, code, runtime, and retained execution files match. It retries incomplete attempts in a fresh directory and leaves earlier evidence available for inspection. This covers development cases with retained artifacts. Benchmark shards, sealed manifests and Kaggle bundle resumption are still pending.
- `tests/test_fault_hooks.py` covers deterministic mutation for development cases, stage-hook behavior, separate evaluator facts, and held-out rejection. CI run 60 on commit `fd46f33` passed the full suite and wheel build on Windows and Linux with Python 3.10 and 3.13. The local verification environment also passed the full suite with the lookup case integration.
- The v1 contract files are unchanged. Existing commands keep the v1 default. The explicit command `dic run --month 2023-01 --contract-version v2` selects the v2 path. No M2a detector, distribution threshold, or experimental evaluation is enabled by this proposal. The fault hook module is present but is not wired into an end-to-end run.

## Still required before Phase 1 acceptance

- The 48-file source manifest was generated from the local raw directory and all files matched pinned SHA-256, byte size, row count, physical schema and cohort. Its manifest digest is `11db74829a7820870666a5ada355ce3f684366ec038446ebd9647b9996283b71`. Run `python experiments/m2a/validate_source_manifest.py --raw data/raw --out experiments/m2a/audit/source_manifest_v2.json` to reopen and validate the raw files again. The compact `--verify-only` mode checks the report schema, manifest digest, contract hash and audit consistency, but does not reopen Parquet or independently reproduce row-level results.
- Extend resumption to the benchmark matrix and enforce the access boundary for all comparison methods. The four development cases now reach the worker. The held-out execution path still requires implementation and the protocol freeze before any held-out evaluation.
- Implement and freeze the production-available integrity checks from independently justified rules, then exercise detection and diagnosis methods separately. Distribution alerts remain disabled under protocol v1.2 and are not a blocker for the current scope.
- Build resumable per-case evaluation, metrics and the results verifier only after hook and detector fixtures pass. M2a remains unfrozen and unevaluated.

Protocol v1.2 and the D9 deferral are adopted on `main`; the full M2a protocol remains unfrozen until the remaining oracle and catalog review gates pass.

No M1 evidence or tag is changed by this proposal.
