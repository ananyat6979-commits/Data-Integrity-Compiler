# M2a Experimental Protocol v1.1

**Status:** Phase 0 draft for review. Do not begin Phase 1 code until this protocol, the catalog schema, the proposed mechanism matrix, and all independent oracle specifications have been reviewed. M1.1 acceptance remains a separate gate. Fault mechanisms and numerical thresholds must be justified before the development split is implemented; all evaluation choices are frozen at the Phase 3 checkpoint.

## Objective and limits

M2a tests whether diagnosis, including controlled counterfactual replay, improves localization of silent data corruption over simpler methods on the documented NYC TLC Yellow Taxi pipeline. It is not a formal verification result and does not support claims about arbitrary enterprise pipelines. The contract declares expected behavior; runtime checks observe it; independent references establish correctness where available; diagnosis ranks causes; interventions test explanations; and the publication gate decides whether outputs can be released.

The M1 January 2024 evidence remains bound to its historical contract hash and is not rewritten to match a later contract. M2a uses a separately versioned contract v2 where TLC columns vary across the selected years. A valid historical evidence bundle remains valid if the repository contract later changes; its verifier reports the current-contract comparison separately.

## Fault catalog and independent evidence

Phase 0 produces and reviews three versioned artifacts before Phase 1 code: `schemas/fault-catalog-v2.schema.json`, `experiments/m2a/catalog/fault_catalog_v2.json`, and `docs/m2a-independent-oracles-v2.md`. The full target has eight distinct mechanisms, two per stage. The catalog also has one supplemental underdetermined abstention control, outside the eight-mechanism factorial matrix and excluded from recall. Each split has one whole mechanism from every stage, and each split includes both contract-visible and contract-silent externally detectable cases. Each mechanism has three declared severities and seeds 11, 29, and 47, yielding 72 repeated executions. These variants are not 72 independent mechanisms. The catalog author knows the held-out assignments; this is disclosed as a limitation. The full four-stage, eight-mechanism matrix is the primary target. If a proposed mechanism lacks a defensible oracle or meaningful severity, replace it with another mechanism in the same stage and split, then review the replacement before Phase 1. The separately pre-registered minimum engineering benchmark is defined in the schedule section. It is not full M2a acceptance and cannot be selected after held-out outcomes are seen.
The M2a contract v2 draft must make cleaning a complete retention predicate: every input row satisfying all rules is retained exactly once, and source identity is available for reconciliation. It must also verify that each lookup join uses the declared key by checking the joined lookup key against the source row's configured key. These new v2 checks make cleaning_fare_threshold and join_wrong_key contract-visible for M2a; M1 did not implement these checks. The catalog labels are conditional on freezing these v2 semantics before Phase 1.

Before Phase 1 code, draft the M2a contract v2 semantics, then review and freeze the versioned catalog with one record per mechanism: stable ID, stage, transformation, locus (`code_fault` or `data_fault`), class, deterministic mutation procedure and parameters, severity, seed policy, original-implementation behavior, affected records/keys/partitions/metrics, oracle, available evidence, expected detectability and rationale, impact function and tolerance, eligible intervention type, and split. Fault classes are:

- `contract_visible`: violates an existing declared invariant.
- `contract_silent_externally_detectable`: passes declared checks but conflicts with an independently justified oracle or additional production-available evidence.
- `underdetermined`: available evidence cannot distinguish the correct and faulty results. This is an observability limit, not an ordinary recall miss.

Every detectability label has a written rationale and is frozen before detector tuning. Cases are not reclassified after results. The injector owns private execution labels and mutation parameters; the detector receives a separate allow-listed input bundle with no mutation details, expected outputs, evaluator labels, or oracle-derived hints. Test the assembled detector bundle for leaked fields as well as failing on any attempt to open a path whose basename begins `ground_truth`. The evaluator uses separate private labels and calculations.

Every proposed mechanism must have a meaningful independent oracle and severity before it enters the frozen matrix. Reference transformations are checked against hand-computed fixtures and separate reconciliation; they are not trusted merely because they differ from the faulty code. When an oracle establishes only part of the output, score only those properties. The catalog author knows the holdout assignment, which remains a threats-to-validity limitation; no broad mechanism-generalization claim is made from a handful of held-out mechanisms.

Hooks are owned by the harness and placed at ingestion, cleaning, join, and aggregation boundaries. They are invisible to the detector and absent from reference code paths. Implement the fixed matrix of two distinct mechanisms per stage, three meaningful severities, and seeds 11, 29, and 47. Hold out whole mechanisms while keeping both detectable classes and all four stages represented in each split. Do not split close variants and call them independent.

## Detection and diagnosis protocol

Keep two result tables. The detection table has four arms: the full system under test, row-count-only, schema-only, and contract-rule-only. The full system combines contract rules with frozen silent-fault checks. Derive silent-fault checks from source documentation, data-dictionary constraints, domain invariants, or general pipeline conservation, never from held-out outcomes. Disclose each check and freeze its thresholds before held-out generation. Timestamp-distribution checks may alert or block only under the predeclared schema-cohort, regime, and baseline-window rules. The diagnoser table has four arms: lineage-only, observed-divergence from ordinary pipeline logs, reference-assisted divergence using trusted stage outputs, and counterfactual replay. For the conditional diagnosis comparison, the frozen full-system detector's production-visible alert is the common trigger: every diagnoser receives the same alerted cases and only the evidence allowed for its method. Report diagnosis accuracy on that common alerted subset. Separately report end-to-end success over all eligible cases, which requires a correct alert, correct localization, and a successful oracle-validated intervention. Never describe counterfactual replay as a detector.

Counterfactual replay supports two intervention types:

1. `replace_transformation`: replace one identified code transformation with a validated reference transformation.
2. `replace_input`: replace one corrupted data input with a trusted version, then replay the downstream stages from the same upstream inputs.

Each catalog mechanism declares its locus and eligible intervention type in eligible_interventions. Code faults use replace_transformation; data faults use replace_input only when an independent trusted input exists. The separate underdetermined control declares an empty intervention list and expects abstention. Input replacement is not available merely because an evaluator has private labels.

## Controls, metrics, and analysis

Use January 2022 through December 2025: 2022 supplies the 12-month warm-up, and January 2023 through December 2025 are the 36 monthly exact-reconciliation controls. Under the current regime rule, only 2023 and 2024, 24 months total, are eligible for distribution-alert scoring; all 12 months of 2025 are distribution-ineligible because the January 2025 regime has fewer than 12 prior eligible months. This recent period uses zone IDs and avoids older coordinate-based TLC schemas. Before contract v2 is written, inspect and record the schema, types, and data-dictionary applicability for all 48 source months. Keep the M1 evidence tied to its historical contract hash. A month is `independently_verified_clean` only when its immutable official source checksum is recorded, Polars `1.44.2` recomputation independently agrees on declared per-stage row counts, null counts, exact fare sums, and join multiplicities, and its columns, types, date coverage, and applicable ranges satisfy the TLC data dictionary. Implement this recomputation in Polars as a separate calculation from the DuckDB pipeline. Findings are classified separately as independently verified clean, genuine source anomaly, or unresolved/disputed source anomaly. A genuine source anomaly correctly detected by the pipeline is not a false alarm.

The statistical baseline is the preceding 12 eligible months from the same contract, source-schema cohort, and declared operating regime. Do not use calendar-month-of-year strata because one year supplies only one observation per calendar month. Distribution checks may use weekday-by-hour cells only when each cell has at least 30 baseline observations; otherwise that check is ineligible for the cell. The January 2025 congestion-pricing change starts a separately reported regime. Do not compare it to the pre-change regime. A month without 12 eligible same-regime history months is ineligible for a distribution alert; exact reconciliation checks still run. The 2022 warm-up months are calibration-only, not scored controls. Exclude known regime breaks and independently identified source anomalies from calibration and report them separately. Freeze thresholds and alert/block conditions on development controls before held-out evaluation.

The false-positive unit is one independently verified clean monthly run with the relevant check eligible. Report separate numerators and denominators for the full run-level decision and distribution-check-only alerts, with binomial intervals where assumptions are defensible and dependence caveats for shared source generation and pipeline configuration. Report 36 monthly exact-reconciliation controls and the actual eligible denominator for each statistical check. The distribution-alert denominator is at most 24 under the current regime boundary. Report source-anomaly detections and unresolved findings separately. Fault recall uses the mechanism as the inference unit: give detected and missed mechanism counts and descriptive per-mechanism results. Severity and seed executions are correlated repeats, not independent mechanisms. Do not pool them to imply a large sample; any interval must state and justify its independent unit. With four held-out mechanisms, results are descriptive and no pooled generalization claim is made.

For every run, record whether it was published, blocked, or abstained; whether that decision was correct against the independent oracle; and whether a fault escaped publication. Report alerting, localization, root-cause rank, impact accuracy, and causal validation as separate outcomes. Top-1 is primary. Do not report top-3 with four stage candidates. Impact metrics are mechanism-specific: exact row/key differences, absolute and relative numeric error, or declared distribution comparisons. For zero, null, or values below a predeclared epsilon, report absolute error and omit unstable relative error. ML impact is deferred.

Report alert time, validation overhead, diagnosis time, and publication-decision time separately. Compare detector-enabled and detector-disabled runs in fresh subprocesses on the same data and environment, at least five repetitions, reporting distributions. Peak working set is a controlled empirical comparison, not exact attribution of allocated bytes.

Use /kaggle/tmp only for disposable scratch and intermediate replay materializations. If a defect is found in the frozen detector or protocol, create a new version and a new untouched holdout. Do not patch and rerun the same cases while calling them untouched. ## Acceptance and threats to validity

Full M2a is accepted only when m2a-frozen exists; one command reproduces evaluation from the persisted raw per-case outputs; scripts generate every result table; an independent results verifier passes and detects altered or missing evidence; and the report includes misses, false alarms, ambiguous diagnoses, residual damage, publication decisions, resource distributions, coverage by method, separate abstention-control results, and a threats-to-validity section. Report the number of distinct mechanisms detected and missed. Do not treat 72 severity/seed scenarios as 72 independent mechanisms. The minimum engineering benchmark does not satisfy full M2a acceptance.

The threats-to-validity section must cover catalog-author knowledge of the split, small held-out mechanism count, source-month dependence, TLC source anomalies, schema-version and regime boundaries, oracle incompleteness, threshold selection, detector evidence access, and the limited scope of the dataset. A defect in the frozen implementation invalidates that version's held-out result; it requires a new version and new holdout. It must also cover shared specification risk: Polars is an independent implementation, but it applies the same declared semantics and data dictionary and therefore cannot rule out a shared conceptual error in those specifications.

The November 17 checkpoint reviews pilot results, oracle validity, costs, and progress; it does not reduce scope. Phase 2 builds development detectors and references using development cases only. At the November 24 checkpoint, record the full-scope or minimum-benchmark decision before held-out generation. Phase 3 freezes and hashes the protocol and implementation artifacts, then tags `m2a-frozen` before any held-out case generation. Phase 4 generates held-out cases and evaluates the complete matrix.
